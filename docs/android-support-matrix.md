# Android support matrix (audit)

Audit date: 2026-11-21. This matrix describes the Android app only. The full screenshot-by-screenshot HTTP Custom parity scope is tracked in [`http-custom-reference-matrix.md`](http-custom-reference-matrix.md); planned controls are not supported features. Android signing and release gates are tracked in [`android-release-readiness.md`](android-release-readiness.md); the current release status is blocked.

## Implemented on `main` (PRs #1–#5; baseline `d3ad310`)

| Area | Actual Android behavior |
| --- | --- |
| VMess, VLESS, Trojan, Shadowsocks | Parsed and built with the pinned Xray-core engine; the supplied live subscription smoke test checks all four. |
| VLESS/Trojan REALITY | REALITY keys, short IDs, SNI, fingerprint, and spiderX are retained. Invalid/missing public keys or malformed short IDs are rejected at import. |
| XHTTP and HTTPUpgrade | URL path/host/mode/`extra` and HTTPUpgrade path/host are mapped into Xray stream settings. XHTTP/REALITY and HTTPUpgrade configs are validated against the same Xray-core release as the Android AAR. |
| UDP packet engine | Persistent selector between HevSocks5Tunnel (default on Android 10+) and Xray native TUN. Older Android versions fall back to Xray native TUN because the pinned Hev AAR declares API 29. This is **not** the HTTP Custom BadVPN/UDPGW selector. |
| Engine logs | Warning, Verbose (Xray `debug`), and Error levels; takes effect on the next connection. |
| Log retention | Persists a numeric cap from 100–10,000 and immediately trims the actual in-memory entry buffer (multiline entries count once). JVM range/trimming tests and KVM save/reset/cancel/invalid/activity-recreation coverage passed in post-merge run [44889231145](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44889231145). |
| Live traffic rate and unit | Samples actual Xray outbound byte-counter deltas over monotonic elapsed time; the Beranda displays upload/download rate in B/s or bps while cumulative session totals remain bytes. JVM rate/conversion/format tests and KVM preference/recreation coverage passed in PR #3 CI run [44891577574](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44891577574). |
| SOCKS5 port | Persists and validates ports 1–65,535; rejects invalid input before connecting and applies the saved port on the next connection. |
| Destination sniffing | Persists the switch and passes it into generated Xray config for active inbounds; changes apply on the next connection. This does not implement the full V2Ray routing-only/rules UI. |
| VPN DNS and MTU | Persists two numeric IPv4 DNS servers and MTU (1280–9000); Android `VpnService.Builder`, Xray TUN config, and Hev config consume the saved values on the next connection. Unit/config generation tests passed in merged CI; KVM run [44885399758](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44885399758) passed the DNS/MTU UI persistence and invalid-input instrumentation cases on x86_64 Android. This does not establish live DNS, VPN routing, or leak behavior. |
| Per-app VPN | Persists “all apps”, “only selected”, and “all except selected” package policies; the active policy is translated to Android `VpnService.Builder` allow/disallow calls, always excluding NusaTunnel to avoid VPN recursion. JVM planner tests and KVM editor/persistence/recreation tests passed in PR #3 run [44893277188](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44893277188). Controlled included/excluded app traffic has not yet been verified, so end-to-end routing is not claimed. |
| Keep CPU awake and system settings shortcuts | Merged PR #4 adds a persisted opt-in that holds a real Android `PARTIAL_WAKE_LOCK` only while the VPN interface is established; the lock updates immediately when the preference changes and releases on interface closure/service teardown. It also opens Android app-info battery controls and VPN settings. PR #4 CI [44895022995](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44895022995) passed JVM policy tests and 11 KVM tests (0 failures), including preference recreation, real `PowerManager` lock acquire/release, and Settings intent resolution; final PR run [44895607868](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44895607868) and post-merge run [44895981845](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44895981845) passed. This does not request battery exemption, configure Always-on/lockdown, prove actual VPN traffic, or verify OEM/physical-device behavior. |
| IPv6 route | IPv6 remains routed through the VPN. There is deliberately no off switch yet because that could leak IPv6 outside the tunnel until a real packet-blocking path is validated. |
| Auto Ping | Opt-in: pings the selected server every five minutes only while the app is foregrounded and the VPN is disconnected. It does not provide the reference's Keep-alive/Reset/Aggressive modes or advanced controls. |
| Connection Check (HTTP(S)) | Persists a validated HTTP(S) URL, interval (5–3,600 s), timeout (1–60 s), maximum attempts (1–10), and opt-in stop-on-failure. After Xray core reports connected, a GET runs through its local SOCKS5 inbound with hostnames sent to SOCKS5; HTTPS uses platform trust plus hostname verification, and HTTP 200–399 is success. Retries stop on success or after the configured limit (1-second retry delay). VPN disconnects only when every attempt in a cycle fails and stop-on-failure is enabled. Monitoring stops on disconnect/error/service teardown. PR CI [44905947111](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44905947111) and post-merge CI [44906424937](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44906424937) passed; KVM recorded 12 tests, 0 failures/errors/skips. JVM tests use a fake SOCKS5 HTTP/TLS service and KVM verifies UI/persistence; live Xray/VpnService TUN traffic is **not yet verified**. |

Hev mode uses the Android VPN TUN fd in HevSocks5Tunnel and keeps Xray as a local SOCKS5 proxy. Its native worker is health-checked and stopped before Xray during teardown. The Xray-native mode remains available as a fallback. Neither choice is represented as BadVPN.

## Not implemented / not to expose as active controls yet

| Requested area | Status |
| --- | --- |
| SSH, payload proxy methods, HCR | No SSH profile parser/forwarding engine or HCR exchange exists. |
| SlowDNS | No DNS-tunnel implementation exists. |
| OpenVPN | No OpenVPN core or `.ovpn` profile importer exists. |
| Psiphon | No Psiphon SDK/core integration exists. |
| BadVPN / UDPGW | No BadVPN engine or configurable UDPGW endpoint/port exists. |
| Advanced connection behavior | Per-app VPN modes and package selection are implemented and wired to Android's `VpnService.Builder`; UI/persistence and policy tests pass, but selected-versus-excluded app traffic has not yet been verified. Merged PR #4 implements the optional active-interface CPU wake lock and links to Android app-info/VPN settings. Connection Check is implemented on `main` via PR #5; PR CI [44905947111](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44905947111) and post-merge main CI [44906424937](https://github.com/XbibzOfficial777/NusaTunnel/actions/runs/44906424937) pass, but live Xray/tunnel traffic validation is pending. Automatic reconnect, Auto Ping modes/recovery, Share Net/local proxy, and associated controls remain unimplemented. |
| Advanced V2Ray/Xray settings | Complete profile GUI/JSON editor, configurable routing rules/presets, custom DNS hosts, asset manager, and other screenshot options are not implemented as a complete feature set. |
| UDP Custom tuning | Upload/download rate, receive window, idle timeout and Path MTU discovery controls are not implemented. |
| Response checker | HTTP/SNI/UDP/DNS checks, manual proxy selection and custom headers/body are not implemented. |
| Hardware ID / Access ID authorization | The UI/service contract is absent. The reference's “Get ID” requires an approved authorization endpoint and response/privacy contract; no fake success path is acceptable. |
| General and navigation parity | The numeric log cap 100–10,000 is implemented on `main`; live throughput units (B/s or bps) are implemented in PR #3 and its JVM/KVM checks passed in run 44891577574. Language/theme/dynamic color and several other screenshot controls remain missing. The references show Home / Profiles / Settings / Guide while this app uses Beranda / Server / Atur / Log; Guide content is not supplied, so behavior must be agreed without silently removing Logs. |

These require their own real runtime/configuration support, tests and lifecycle handling. They are not implemented by Xray's VMess/VLESS/Trojan/Shadowsocks outbound builder. The supplied subscription also contains Hysteria2/`hy2` and SSR links, which remain outside the Android parser's four supported outbound protocols. The feed is live and can change; exact counts are not a stable contract.
